# TOKENS_OPTIMIZATION

Цель: минимум токенов без потери качества (≥5x снижение расхода контекста). Контекст = деньги: каждая итерация
цикла пересылает всю историю (даже кэшированно). Соблюдай правила ниже по умолчанию.

## 1. Чтение файлов
- Перед чтением проверяй размер (`wc -l` / `wc -c`). Файлы > 200 строк читай только
  точечно: `rg` с `-C`, либо диапазоны строк (`offset`/`limit`).
- Не читай целиком «на всякий случай»: lock-файлы, бандлы, генерированный код,
  `node_modules`, `dist`, `*.min.*`, бинарники, справочные каталоги в `docs/reference/`.
- Уже прочитанное в этой сессии не перечитывай — переиспользуй. Повторное чтение
  только точечным диапазоном и только если данные могли устареть.

## 2. Вывод команд и инструментов
- Ограничивай вывод на уровне команды: `| head -n 50`, `| rg <pattern>`, флаги тестов
  «только падения» (`-q`, `--reporter=dot` и т.п.).
- Не тяни в контекст полные логи, JSON и диффы: сначала выжимка
  (`git diff --stat`, `jq select`), потом точечные фрагменты.
- Вывелось неожиданно много — обрежь и явно пометь в отчёте, что обрезано.
- Широкий поиск делегируй сабагенту, в основной контекст возвращай выжимку.

## 3. Ответы и правки
- Отвечай сжато: не пересказывай и не цитируй код, уже лежащий в контексте;
  ссылки вида `path:lines` вместо простыней.
- Минимальные диффы; соседний код вне задачи не трогать.

## 4. Итерации и план
- Принятый шаг с подпунктами выполняй автономно за один прогон, без подтверждений
  на каждый подпункт.
- Подтверждение спрашивай ТОЛЬКО для необратимого/рискованного (удаление, миграции,
  force push, внешние отправки).
- Перед серией действий — короткий план (3–7 пунктов); дальше работай по нему,
  не перепланируй с нуля на каждой итерации.

## 5. Жизненный цикл контекста
- Веди `SESSION_NOTES.md` (append-only, сжатые буллеты): решения, карта файлов,
  открытые вопросы, текущее состояние. Обновляй после каждой завершённой вехи.
- При контексте > 40–50% окна (или по сигналу пользователя) сам предложи:
  компакция сейчас ИЛИ хэндовер — новая сессия, стартующая с `SESSION_NOTES.md`.
  Не жди автокомпакции клиента.
- В конце сессии обязательно обнови `SESSION_NOTES.md`: следующая сессия не должна
  тащить эту историю.

## 6. Лог расхода (`SESSION_LOG.md`)
- После каждой вехи дописывай ОДНУ строку:
  `[веха] итераций: N | контекст: ~Xk ток | чтений: Y (точечных Z) | усечений вывода: K`
- Размер контекста бери из статуса клиента, если доступен; иначе оценивай консервативно.
- Точные `$` не выдумывай: биллинг живёт в OpenRouter/провайдере, твой лог — про динамику.
  Если пользователь вставил цифры провайдера за сессию — занеси и используй
  для калибровки оценок.

## 7. Исключения
- Правило конфликтует с качеством (нужен весь файл для понимания архитектуры) —
  нарушь осознанно и одной строкой объясни почему.

## 8. Архитектурные механизмы экономии токенов в Ruflo (v3)
- **MCP Tool Profile (`CLAUDE_FLOW_MCP_TOOLS`)**: по умолчанию в `.claude/settings.json` и `.mcp.json` задан профиль `core` (~42 ключевых инструмента координации ≈ 7.2k токенов вместо 387 инструментов ≈ 82k токенов). Все 387 инструментов остаются доступными для вызова (`tools/call`) и поиска (`guidance_brain`). Для полного листинга схем задайте `CLAUDE_FLOW_MCP_TOOLS=all`.
- **Компактная сериализация MCP (`formatMcpToolResult`)**: ответы `tools/call` сериализуются в однострочный JSON без лишних отступов (для pretty-print: `CLAUDE_FLOW_MCP_PRETTY_JSON=1`) и ограничиваются `CLAUDE_FLOW_MCP_MAX_OUTPUT_CHARS` (по умолчанию 32000 символов).
- **Бюджет каталога скиллов и агентов**: `skillListingBudgetFraction = 0.012` (1.2% окна вместо 6%), а мод `ruflo-mods` включает `agentTrim: true` (скрывает неиспользуемые типы агентов, экономя ~4,236 токенов/запрос) и `compactCarry: true` (сохраняет состояние роя и клеймов при `/compact`).
- **Фоновый демон (`daemon.autoStart = false`)**: фоновые воркеры запускаются только явно (`npx ruflo daemon start`), исключая скрытый расход токенов в простое.
